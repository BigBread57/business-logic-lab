# Generated data and exploratory histories

Derive valid synthetic inputs from structural API constraints AND agreed semantic preconditions: object references, ownership, lifecycle state, permitted parent/depth, query checks and uniqueness. Generate arbitrary suitable values and combinations rather than relying only on a fixed example. Validate setup and dependencies before attributing a failure to the target function. Keep deliberately invalid and boundary inputs separate from valid controls.

`scripts/explore.mjs` provides dependency-free seeded generation for a deliberately limited JSON-schema-like subset. Run its `--help`; `sample` saves seed and concrete samples. Supported types are object/array/string/number/integer/boolean/null, required properties, enum, numeric and length bounds, restricted anchored ASCII patterns, const, anyOf, uniqueItems and dependentRequired. Unsupported keywords and patterns fail explicitly: this is not a full JSON Schema/OpenAPI generator. Resolve references and semantic conditions through project schemas/factories, Hypothesis/fast-check or agent-prepared fixtures. A syntactically valid generated object is not automatically a valid business fixture.

For every selected function, plan several distinct valid datasets and action sequences, plus applicable invalid/boundary cases. Vary actor, ownership, values, number/order of actions, repeats, state and concurrency schedules. Record requested versus achieved repetitions/classes within the shared budget; skipped cases remain gaps. Preserve actual concrete input, created IDs, seed, schema/generator version and prerequisites. A seed alone cannot replay remote IDs or transaction scheduling. Do not promise exhaustive exploration of infinitely many possible inputs.

## Two kinds of conclusions

In conformance mode, compare observations against approved rules and preserve the original expectations for regression. In exploratory mode, execute scoped variations without requiring a complete business model; record observations and unanswered questions for later business review. Independently approved invariants may still reveal violations. Acceptance of an unusual input is not itself a defect, and an unapproved expected result must not produce a business pass/fail.

HTTP and journal now support `mode: observation` with a question and no rule IDs/assertions; see [runtime.md](runtime.md) for the executable contracts. Observations appear in the ordinary report without business verdicts or rule coverage. That reference also describes bounded state search, reset verification and failure-preserving sequence reduction. Native adapters share the run budget through admission/completion leases; `explore.mjs` history alone remains a recorder without transport enforcement.

## Record, correlate, then analyze

Use exported `appendIntent`, `appendResult` and `appendObservation`, or a compatible transport recorder. Intent requires `id`, `actor`, application `role`, isolated `session` and `correlation`. Store the operation/target, concrete inputs, before-state, causal links and start time in JSON data. Result inherits identity and stores the response/rejection/error, completion time, side effects and evidence references. Save intent before acting; if completion is uncertain, preserve the unmatched intent and reconcile before retrying. UI actions link to related HTTP records and screenshots; credentials and sensitive fields are redacted.

Append-only `history.ndjson`, exclusive action/result claims and per-action identity snapshots survive context loss. `analyze`/`inspectHistory` detects structural problems and unfinished actions; it does not judge domain logic. The coordinator analyzes the combined history against approved invariants and valid sequential outcomes: uniqueness, parent/cycle/depth, private access, partial writes, UI/API divergence and cross-account visibility. Preserve shared-object barriers, overlapping request intervals and eventual state; timestamp order alone does not prove transaction order. Include exploratory outcomes and trace gaps explicitly, not just defects. Redaction covers credential fields/known secret values, not every possible personal-data format; use synthetic datasets and inspect external evidence before sharing.
