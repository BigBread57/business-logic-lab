# Native test artifacts

Import an existing JUnit XML file into a new output directory:

```sh
node .agents/skills/business-logic-qa/scripts/test-artifacts.mjs import --out ./evidence/test-1 --junit ./junit.xml --command '["npm","test"]' --versions '{"node":"v22"}' --collection ./collected.txt --coverage ./coverage.json
```

`run` accepts the same arguments, requires `--command` as a JSON argv array, and executes it directly without a shell. `--cwd` sets the child's working directory; relative JUnit, collection and coverage paths are resolved there. `--env '{"CHILD_NAME":"EXISTING_ENV_NAME"}'` maps child variables to existing environment variables without passing their values as arguments; referenced values are added to the sanitizer. The child otherwise inherits the current environment. `--timeout` is milliseconds, defaults to 300000 and is capped at 3600000. The output directory and every specified evidence path must not already exist before the child starts. The CLI returns nonzero for a failed command or missing JUnit. The process exit code, signal, timeout flag, sanitized stdout and stderr, and truncation flags are recorded even when JUnit is missing. Each stream is capped at 10 MiB. On POSIX, timeout kills the child's process group; descendants that leave the group may survive. On Windows it kills the direct child. Callers must choose commands and environments they trust. `--help` lists options.

The module exports `importTestArtifacts({ out, junit, command, versions, collection, coverage })` and `runTestCommand` with the same options plus `timeout`, `cwd`, and `env` (a mapping of child variable names to existing environment variable names). Each returns the manifest; a missing JUnit after execution returns a manifest with `junit: null`. Other malformed artifacts can cause an error after execution evidence has been saved. Paths are filesystem paths; the output directory must not exist and its parent must exist. Imports create files exclusively and never overwrite an existing capture. An interrupted write can leave an incomplete directory; use a new output path for another attempt.

The manifest records each case's name, class, suite path, attributes, outcome and failure, error or skip reason, alongside command argv, versions, optional exit details, original byte counts and SHA-256 hashes. Null fields and `missing` flags distinguish absent optional metadata. The original text is saved after the shared sanitizer removes recognized bearer tokens, sensitive URL parameters and values of environment variables whose names indicate credentials; object keys indicating credentials are redacted as well. Sanitization deliberately changes any matching case, command or version text. Avoid embedding other secrets in input; the sanitizer cannot discover every secret. Hashes identify original bytes, not the sanitized copies. Collection and coverage are opaque text artifacts, not independently interpreted or proof of coverage.

The built-in JUnit reader supports UTF-8 XML up to 10 MiB per source, standard escaped and numeric character references, comments, CDATA, nested suites, testcase attributes, and single failure, error or skipped outcomes. DTDs, entity declarations, arbitrary processing instructions, malformed XML and unsupported structures are rejected. It is not a general XML parser; runner-specific constructs should be verified before relying on the import. Coverage evidence is optional and no exhaustive product coverage is inferred.

The flat testcase-under-testsuites form emitted by Node's JUnit reporter is supported. Captured copies live under a unique `captured-UUID/` directory so a runner can emit its source JUnit inside the reserved output directory without copy-name collisions. Follow the relative `artifact` fields in manifest.json. Existing source artifacts are not modified; raw originals may therefore remain alongside sanitized copies. Missing JUnit still preserves any collection/coverage files actually produced.

The runner records a suite invocation, not each application operation inside that suite. It does not automatically join the QA operation meter. Instrument external actions inside the native harness through the shared runtime when a common budget is required; otherwise report the accounting gap rather than equating a suite invocation or test count with application operations.
