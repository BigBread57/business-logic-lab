# Design

## Boundary

A Codex skill supplies reasoning and native subagent/browser coordination. A Node 22+ standard-library CLI supplies deterministic state, policy validation, deadline-aware HTTP execution, load bounds, evidence storage, report generation and regression replay. This is an instruction package with helpers, not a new model-hosting service.

## Files

- `.agents/skills/business-logic-qa/SKILL.md`: entrypoint and mode routing.
- Skill references: knowledge, exploration/orchestration and interservice/regression guidance.
- Skill assets: example profile, knowledge bundle and HTTP scenario.
- Skill `scripts/qa.mjs`: public CLI and exported functions for tests.
- `tests/qa.test.mjs`: local HTTP integration and state/policy regression checks.
- `projects/rsa/`: inspected sources, knowledge draft and incomplete environment profile.
- `docs/usage.md`, `docs/verification.md`: invocation, evidence and outstanding prerequisites.

## State and execution

Run directories contain immutable configuration and knowledge snapshots plus original deadlines. Each experiment obtains an exclusive claim and writes an independent result atomically; uncertain claims are never auto-retried. Credentials are environment references resolved only during execution. HTTP redirects are refused; origins and permissions are checked before sending requests. Parallel groups use distinct actor credentials and explicit shared resource variables. Polling is bounded by both the observation window and the original run deadline. Browser workers use independent contexts and journal evidence through the helper.

Reports distinguish outcomes from environment failures and documentation gaps. Assertion-bearing scenarios reference approved rule IDs. Generated Node tests replay saved scenarios with a fresh run and original assertions; framework-native target-repository tests may additionally be generated by Codex following that repository's conventions.

## Verification

Use Node's test runner with a local HTTP server to exercise actual request handling, parallel actors, eventual observations, permission refusal, stale approval, secret redaction, interrupted claims, coverage/reporting and a generated regression that fails for an intentionally violating response. Such harnesses verify the tool; they are not the demonstration application the user declined. Validate the skill frontmatter and OpenSpec. Live RSA execution remains dependent on an approved rule bundle and usable endpoint/accounts.
