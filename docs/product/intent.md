# Замысел

## Подтверждено пользователем — 2026-10-22

Пользователь хочет передавать модели инструкции о проекте, доступных API, бизнес-логике и исходном коде. Агент должен на этой основе самостоятельно проверять функциональность и бизнес-логику с разных ракурсов, работать под разными ролями, создавать нагрузку, находить нестыковки и писать отчёты.

Из предыдущего обсуждения: нужен запуск по заданию вроде «тестировать функционал 30 минут», организация документации и управление контекстом; возможна координация нескольких агентов и нескольких пользователей.

Ответы первого раунда: поставка в виде навыка и инструкций для существующих агентов. Есть эталонный бизнес-процесс; любые нестыковки, неописанные процессы и расхождения с кодом фиксируются. Первые среды выполнения — локальный Docker или dev. Конкретные хосты, полномочия и нагрузочные лимиты ещё не согласованы.

Второй раунд уточняет предыдущий: первая версия для Codex. Агент готовит пакет знаний, пользователь согласовывает правила. Обязательны UI, API и чтение кода; БД и события используются при наличии доступа. Полномочия настраиваются: локальный стенд — полный доступ в его пределах, dev — ограниченный. Структура команды и время работы настраиваются; по умолчанию координатор с исполнителями и общий бюджет 20 минут. Конкретные лимиты нагрузки определяются конфигурацией проекта, а не универсальным числом для любой системы.

## Требования к результату, вытекающие из запроса

- Принимать описание тестируемого проекта и источники ожидаемого поведения.
- Генерировать гипотезы и сценарии, а не только исполнять заранее написанный happy path.
- Исследовать полные процессы, запрещённые действия, роли и владение объектами, повторы, порядок действий, конкуренцию и поведение под нагрузкой.
- Исполнять доступные проверки на работающей системе через согласованные интерфейсы.
- Сопоставлять наблюдения с бизнес-правилами и сохранять доказательства.
- Выдавать отчёт о находках, неоднозначностях и фактическом покрытии.
- Сохранять ход работы вне контекста модели, обеспечивать продолжение после прерывания.

Третий раунд: первая проверка сразу на реальном проекте пользователя. При пробелах в правилах агент фиксирует неопределённость и продолжает независимые сценарии. Итог включает Markdown и JSON, покрытие правил, доказательства, replay-сценарии и автоматически созданные регрессионные тесты. Последнее требование заменяет первоначальный ответ Q11.

Конкретные движки, нагрузочные профили и критерии приёмки описаны как предложения в [спецификации](../design/specification.md) и требуют итогового согласования.

## Предложения, ещё не решения

- Координатор распределяет небольшие задания по ракурсам проверки.
- Исполнители ведут отдельные сессии и наборы данных. Согласованный общий объект выделяется только для намеренного конкурентного сценария.
- Аккаунт не равен агенту: один исполнитель может управлять несколькими аккаунтами.
- Результат сценария имеет состояние pass / violation / inconclusive / blocked / not-run.
- Отчёт различает подтверждённый дефект, наблюдавшееся однократное нарушение и гипотезу. Невоспроизводимость гонки не стирает уже записанное доказательство.
- Классификация находки и её серьёзность отделены от уверенности в доказательствах.
- Наблюдения в распределённой системе оцениваются с учётом согласованного времени сходимости и способа получения согласованного снимка.
- Минимизация сценария и повторный запуск выполняются только при возможности восстановить подходящее исходное состояние.
- Текстовый отчёт не объявляет систему корректной целиком по результатам ограниченного запуска.

## Что не обещаем без проверки

- Работу с любой моделью независимо от наличия инструментов, размера контекста и качества следования инструкциям.
- Исчерпывающее покрытие поведения за фиксированное время.
- Детерминированное воспроизведение удалённых гонок только через одновременную отправку HTTP.
- Автоматическое разрешение противоречий требований без владельца бизнес-процесса.
- Изоляцию браузера и данных лишь за счёт создания отдельных агентов.

## Будущая проверка продукта

Пользователь выбрал реальный проект вместо демонстрационного стенда. Репозитории и первый бизнес-процесс ещё не указаны. Проверяем корректность подготовки знаний, изоляцию сессий, выполнение согласованных проверок, доказательства, отчёт и запускаемость созданных тестов. Число найденных дефектов не является гарантированным критерием: в реальном проекте заранее неизвестно число ошибок.
