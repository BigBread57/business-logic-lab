Новые интеграционные тесты используют настоящие локальные HTTP-серверы и дочерние процессы. Они проверяют observation-only init/HTTP/journal/report без oracle, сохранение conformance gates, общий счётчик для разных процессов/транспортов, SDK timeout и uncertainty/reconciliation, multipart/binary байты и ограничение путей/размера/hash, переносимую upload-регрессию с capture между шагами, replay в родительском бюджете, deterministic composite generation, bounded state paths и сокращение сохранённого дефекта с reset перед каждой попыткой. Lifecycle тестируется реальными argv-процессами: свежие аккаунты/namespace, частичная ошибка, автоматическая очистка, retry cleanup и таймаут.

Concurrency-проверки используют явные барьеры вместо предположения, что короткие задержки обеспечивают перекрытие. Runner ограничен двумя параллельными test files, при этом операции внутри тестов и проверки между процессами остаются конкурентными. На загруженной машине прежние короткие окна давали технические таймауты; бизнес-проверки получили достаточное время, а отдельные тесты истечения бюджета сохраняют свои явные короткие ограничения. Неуспешные прогоны не считались доказательством корректности.

## Границы поставки

Общий бюджет действует для сотрудничающих адаптеров через новый протокол и folder proxy с QA_PARENT_RUN. Исторический Python harness ещё использует отдельные счётчики и в автоматически созданном стенде по умолчанию заблокирован: требуется инструментировать его примитивные действия перед смешанным запуском. Полный RSA startup остаётся непроверенным успешным путём на текущей машине.

Генератор поддерживает явно перечисленное подмножество контрактов. Поиск использует предоставленную модель и ограниченный бюджет; native reduction требует evaluator/reset адаптера. Контроль процесса не откатывает уже принятые сервером мутации. [Рабочие контракты и команды](../.agents/skills/business-logic-qa/references/runtime.md).

Проверен общий каталог RSA DevBook и текущий README agent-bootstrap через glab: этот CLI настраивает агентские инструменты машины/репозитория и не предоставляет runtime QA admission или clean application fixtures. Внешняя зависимость не добавлялась; сохранён Node 22 standard library.
